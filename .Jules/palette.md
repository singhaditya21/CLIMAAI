## 2026-05-17 - Safe Async Loading States in Vanilla JS Forms

**Learning:** When adding async loading states to vanilla JavaScript form submissions that are triggered by multiple different buttons (like a login or register form), accessing `e.submitter` is the most reliable way to target the specific button clicked, rather than selecting by `[type="submit"]`. However, `e.submitter` can be `null` if the form is submitted programmatically via JS `form.submit()` or if browser compatibility issues arise. Failing to null-check `submitter` before attempting to modify its properties (like `innerHTML` or `disabled`) will throw uncaught `TypeError`s, breaking the entire submission process. Furthermore, relying on `setTimeout` to restore states is flaky if an async process throws an error.

**Action:** Always wrap state modifications for `e.submitter` in a null-check (`if (submitBtn) { ... }`). Ensure that the original button text/HTML is cached before modification so it can be restored perfectly, preserving icons or complex nested HTML. Use a `try/finally` block around the async operation (e.g. `await api.login()`) and place the restoration logic in the `finally` block to guarantee the UI always recovers its original state, even if the API call fails or throws an exception.

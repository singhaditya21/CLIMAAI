## 2024-05-28 - Robust Async Loading States
**Learning:** When implementing async form submissions in vanilla JS, relying on `e.target.querySelector("button")` fails if buttons lack an explicit `type="submit"`. `e.submitter` is the standard but requires a null check. Safely wrapping state resets (disabling button, restoring original HTML/text, removing `aria-busy`) inside a `finally` block ensures the UI recovers cleanly, regardless of API success or failure. Additionally, when testing these states, simulated async tasks (like `setTimeout`) must be converted to Promises for `finally` to trigger correctly.
**Action:** Always use `e.submitter` (with a null check) for form submission interactions. Place loading state restoration logic strictly inside `finally` blocks, converting simulated async callbacks to Promises when necessary for reliable execution.

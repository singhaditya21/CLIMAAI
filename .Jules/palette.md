## 2024-08-12 - Handling Loading States for Vanilla JavaScript Async Forms
**Learning:** When applying UI loading states (like disabling a submit button) in vanilla JavaScript during async operations, accessing the triggering button requires checking `e.submitter` (for form submissions) or `e.currentTarget` (for standalone clicks), both of which can be null in edge cases. Restoring the button state unconditionally at the end of the async flow is critical.
**Action:** Always wrap state restoration logic (re-enabling the button and reverting its HTML) within a `try/finally` block to ensure the UI does not remain permanently stuck in a "loading" or "disabled" state if the promise throws an error. Safely handle potential null values when accessing the target element from the event object.

## 2026-05-12 - Reliable Async Loading States via `try/finally` and `aria-busy`
**Learning:** During form submissions, exclusively changing visual properties (like text content) for loading states is insufficient for accessibility and robustness. Relying purely on visual text misses screen readers and leaves the button vulnerable to duplicate clicks. Furthermore, simulated API delays or real network failures can cause the UI to remain permanently stuck in a "loading" state if the state recovery isn't guaranteed.
**Action:** When adding loading states to submit buttons during async operations, use `submitBtn.disabled = true` and `submitBtn.setAttribute('aria-busy', 'true')` in JavaScript to explicitly communicate the state to screen readers and prevent duplicate clicks. Additionally, place the state reset logic (restoring original text, `disabled=false`, removing `aria-busy`) within a `finally` block to ensure the UI recovers regardless of API success or failure. Use `e.submitter` to reliably capture the specific button that triggered the submission.

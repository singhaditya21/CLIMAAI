## 2026-08-20 - Ensure Complete Visual Feedback and Restoration on Async Form Submits
**Learning:** During async form submissions in plain JavaScript, users often lack immediate feedback that the process has started, and failing to reset the feedback when the process fails (or succeeds) can leave the UI in a confusing broken state. Furthermore, some form submissions rely on the event's submitter (`e.submitter`), which must be properly verified.
**Action:** When adding visual loading states (like `disabled = true` or opacity changes) to form submission handlers, always ensure a `try/finally` block wraps the async operation to guarantee UI states (like original HTML and styling) are reset. Furthermore, handle `click` vs `submit` events correctly using `e.currentTarget` and `e.submitter`.

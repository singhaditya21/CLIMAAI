## 2024-05-15 - Robust Async Loading States
**Learning:** When implementing visual loading states for async operations in vanilla JavaScript components (like auth forms), relying on success/error paths to revert the button state is brittle. If an unexpected error occurs or the user is redirected, the button might remain permanently `disabled=true` and `aria-busy="true"`. Furthermore, capturing `e.submitter` is the most reliable way to target the specific button that triggered a form submission event, rather than querying for the button within the form.
**Action:** Always wrap the async API call in a `try...catch` and place the UI recovery logic (restoring original text, `disabled=false`, and removing `aria-busy`) inside a `finally` block to guarantee the UI state is reset. Use `e.submitter` on form submit events to target the correct trigger element.

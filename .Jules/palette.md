## 2024-05-24 - Safely Managing Async Loading States in Vanilla JS Forms
**Learning:** When interacting with form submit events in the vanilla JavaScript frontend, capturing the specific button that triggered the submission using `e.submitter` is far more reliable than `e.target.querySelector('button[type="submit"]')`. This avoids errors when forms have multiple buttons or buttons lack explicit `type="submit"` attributes. Furthermore, when implementing async UI loading states (setting `disabled=true` and `aria-busy="true"`), the state reset logic must be placed inside a `finally` block. This guarantees the UI recovers and prevents lockups regardless of whether the API call succeeds or fails.
**Action:** Always use `e.submitter` to target the active submit button in vanilla JS form event handlers, and strictly wrap async API calls in `try...catch...finally` blocks, placing UI restoration logic exclusively in the `finally` block to ensure accessible and resilient loading states.

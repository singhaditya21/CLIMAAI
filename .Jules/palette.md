## 2024-05-18 - Visual Loading States on Auth Actions
**Learning:** Adding visual loading indicators to asynchronous button presses significantly improves perceived performance and clarifies to the user that their action (e.g. login or register) is processing, which prevents duplicate submissions. Handling standard form buttons vs standalone generic elements (e.g. OAuth div or button) requires capturing the actual clicked target safely (such as via `e.submitter` for standard `submit` events or `e.currentTarget` for standard `click` events).
**Action:** When introducing visual loading states via vanilla javascript event bindings, safely isolate the DOM modification block in a try/catch, caching the element reference (`e.submitter` or `e.currentTarget`) and the original state (like `innerHTML` and inline styles), and always implement restoration in a `finally` block to ensure UI stability regardless of API outcome.
